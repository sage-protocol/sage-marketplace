# Layered Prompt Architecture — Reference

## Overview

The layered architecture ensures prompts are modular, composable, and
execution-optimized. Each layer serves a distinct purpose and can be
independently updated without affecting other layers.

## Layer Details

### Layer 1: Identity & Constraints (Always Present)

**Purpose**: Establish who the agent is and what it must never do.

**Template**:
```markdown
## Identity

You are a [role] with expertise in [domains].
Your communication style is [style descriptors].

## Constraints

### Must
- [Absolute requirement 1]
- [Absolute requirement 2]

### Must Not
- [Prohibited action 1]
- [Prohibited action 2]

### Output Format
- [Format requirement]
```

**Guidelines**:
- Keep identity to 2-3 sentences
- Constraints should be testable/verifiable
- Use positive framing where possible ("do X" over "don't do Y")
- Include output format constraints here, not in the directive

### Layer 2: Directive (Always Present)

**Purpose**: The core instruction — what the agent should do.

**Template**:
```markdown
## Task

[One clear sentence describing the goal]

## Process

1. **[Phase Name]**: [What to do]
   - Input: [what you receive]
   - Output: [what you produce]

2. **[Phase Name]**: [What to do]
   - Input: [output from step 1]
   - Output: [what you produce]

## Context

<context>
[Relevant background the agent needs]
</context>

## Examples

<example>
Input: [sample input]
Expected: [sample output]
Reasoning: [why this output is correct]
</example>
```

**Guidelines**:
- One task per prompt (compound tasks use behaviors)
- Process steps should be sequential and dependency-clear
- Include at least one example for complex tasks
- Use `<context>` tags for information the agent needs but shouldn't act on directly

### Layer 3: Behavior Spec (Compound Prompts Only)

**Purpose**: Wire multiple skills into a coordinated execution.

**Schema**:
```json
{
  "behavior": {
    "version": "1",
    "skills": [
      "skill-key-string",
      {
        "key": "skill-key-full",
        "required": true,
        "alias": "optional-short-name"
      }
    ]
  }
}
```

**Stored in**: `prompt.extra.behavior` (or top-level `behavior` in manifest JSON)

**Resolution**: The behavior engine resolves skill keys against:
1. Active library entries
2. Installed skills (on-disk SKILL.md)
3. All local library entries

**Guidelines**:
- Order skills by execution sequence
- Mark truly optional skills as `required: false`
- Use aliases for long skill keys that appear in plan text
- Keep skill count ≤ 10 per behavior (split larger workflows)

### Layer 4: Execution Plan (Auto-Generated)

**Purpose**: The rendered plan the LLM receives when `expand: ["behaviorPlan"]` is used.

**Generated by**: `BehaviorPlan::from_resolved()` + `render_markdown()`

**Structure**:
```markdown
# [Behavior Name]

## Overview
[behavior.content]

## Required MCP Servers
- `server-1`
- `server-2`

## Execution Plan

### Step 1: [Skill Name]
**Purpose**: [skill.description]
**Skill**: `skill-key`
**Source**: library:name
**Instruction**: Apply the [skill name] skill

### Step 2: [Skill Name]
**Depends on**: step-1
...

## Missing Skills
- `skill-key` (install or add to active library)
```

**Not manually authored** — this is computed from the behavior spec.

## Composition Patterns

### Pattern 1: Simple Prompt (Layers 1 + 2)

Use when the task is self-contained with no external skill dependencies.

```json
{
  "key": "rust-error-handling",
  "type": "prompt",
  "content": "## Identity\nYou are a Rust expert...\n\n## Task\nReview error handling..."
}
```

### Pattern 2: Skill (Layer 1 + 2 + metadata)

Use when the prompt should be installable as an IDE skill.

```json
{
  "key": "rust-style",
  "type": "skill",
  "content": "## Identity\n...\n\n## Guidelines\n...",
  "mcp_servers": [],
  "hooks": { "on_install": "..." }
}
```

### Pattern 3: Behavior (Layers 1 + 2 + 3, Layer 4 auto)

Use when the task requires multiple skills coordinated.

```json
{
  "key": "full-code-review",
  "type": "behavior",
  "content": "## Identity\nSenior reviewer...\n\n## Task\nPerform comprehensive review...",
  "behavior": {
    "skills": ["lint-check", "security-scan", "style-review"]
  }
}
```

### Pattern 4: Template (Layer 2 with placeholders)

Use as a starting point for creating new prompts.

```json
{
  "key": "generic-review-template",
  "type": "template",
  "content": "## Identity\nYou are a {{role}} expert.\n\n## Task\nReview {{target}} for {{criteria}}."
}
```

## Quality Scoring Integration

Each layer contributes to the prompt's quality score:

| Layer | Quality Signals | Max Points |
|-------|----------------|------------|
| L1: Identity | Has role + constraints | +3 |
| L2: Directive | Has task + process + examples | +4 |
| L3: Behavior | All skills resolvable | +2 |
| Overall | Metadata complete (desc, tags, model) | +3 |

**Total possible**: 12 (normalized to 10.0 scale)
