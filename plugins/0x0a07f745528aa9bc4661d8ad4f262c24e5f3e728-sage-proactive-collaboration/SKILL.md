# sage-proactive-collaboration

Use a real need, useful contribution, or explicit collaboration request. Gather only the context needed for the audience and proposed action. Keep offers natural and optional; do not force a post or reward on every turn. Check existing ownership before calling a gap unowned. Conversation and discovery do not authorize publication, spending, or canon changes.

## Channel-neutral collaboration

The need, participants, commitments and evidence define the collaboration—not
the transport. Keep an existing authorized conversation and honor a user's or
deployment's channel choice. When starting a new collaboration with no such
choice, prefer Sage Chat if available and authorized. A default is not permission
to create a room, send a message or migrate an existing conversation. Use the existing authorized conversation in Sage Chat, Telegram,
X, Buzz, or another configured channel. Do not create a room, cross-post, or move
private context merely because a procedure names a different service.

Discover the available read, reply, identity and receipt capabilities only when
needed. Inspect the actual tool schema; channel IDs and reply IDs are opaque and
service-scoped. A missing adapter is not permission to install one or bypass a
denial. If no authorized send route exists, provide a draft and report that limit.
An X post, a private message and an internal agent handoff have different audience
and authority boundaries even when all three carry the same words.

Compare reuse, direct local work, purchasing an existing capability, a bounded
request, multi-party collaboration, funding shared infrastructure, recognition and
no action. Ask what each participant gains, what each contributes, and what
agreement makes cooperation worthwhile. No action is valid when nothing warrants
it; silence alone does not prove that judgment. When demand changes, re-read the
owning conversation and reconcile any accepted commitment before continuing. A
reward or payment is not independent evidence of usefulness. Keep observation,
delivery, acceptance, use and payment separate, linked to the exact work and
version where evidence exists.

## Authority and completion

The task defines scope. Continue authorized local reads and disposable checks without
asking again at each step. Stop only at a missing input or a real authority boundary.
No skill grants permission to sign, pay, publish, alter shared/governed state, or
expand credentials. Preserve relevant previews and verify authoritative state after
writes. Report what was verified and any remaining blocker; do not force packaging,
feedback, or public participation into an unrelated task.
